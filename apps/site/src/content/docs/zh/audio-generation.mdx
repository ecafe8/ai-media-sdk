# 音频生成与流式语音

SDK 的音频契约面向文本转语音（TTS）。当前阿里云百炼适配器支持 CosyVoice、
Qwen-Audio、Qwen-TTS 和 MiniMax TTS。调用方只提交 `text`、`voice`、模型和
`providerOptions.aliyun`；文本内容不会被 SDK 解析或改写。

## generateAudio

`generateAudio` 适合等待完整结果的场景。先绑定音频模型，再读取
`result.content` 中的 `AudioContent`：

```ts
import { generateAudio } from "@ai-media/sdk";
import { createAliyunBailianProvider } from "@ai-media/provider-aliyun-bailian";

const provider = createAliyunBailianProvider({
  apiKey: process.env.DASHSCOPE_API_KEY!,
  baseUrl: "https://dashscope.aliyuncs.com/api/v1",
});

const result = await generateAudio({
  model: provider.audio("cosyvoice-v3.5-flash"),
  text: "欢迎使用 AI Media SDK。",
  voice: "longxiaochun",
  providerOptions: {
    aliyun: { format: "mp3", sampleRate: 24000 },
  },
});

const audio = result.content[0];
console.log(audio?.url ?? audio?.base64, audio?.mimeType);
```

`text` 和 `voice` 不能为空；模型能力、格式和家族专属参数在请求前校验。适配器
可能返回 URL、Base64 或两者之一，并携带 `format`、`mimeType`、`sampleRate`、
`channels`、`bitDepth`、`expiresAt` 等元数据。

## streamAudio 与 SSE

`streamAudio` 返回 `AsyncIterable<AudioStreamEvent>`，事件顺序通常为
`sentence-begin`、多个 `sentence-synthesis`、`sentence-end`，最后是 `complete`
或 `error`。这是带 JSON 请求体的 HTTP `POST` SSE，不是 WebSocket，也不应使用
`EventSource`。可使用 `AbortController` 取消：

```ts
import { streamAudio } from "@ai-media/sdk";

const controller = new AbortController();
for await (const event of streamAudio({
  model: provider.audio("cosyvoice-v3.5-flash"),
  text: "这是一段可以逐句合成的文本。",
  voice: "longxiaochun",
  providerOptions: { aliyun: { format: "pcm", sampleRate: 24000 } },
  signal: controller.signal,
})) {
  if (event.type === "sentence-synthesis") {
    // event.audio 是 PCM/Base64 片段，不是一个完整音频文件。
    console.log(event.audio.base64, event.audio.sampleRate);
  }
}
```

浏览器端默认应累积 PCM 片段，在 `complete` 后用采样率、声道数、位深和编码
封装成 WAV Blob，再交给 `<audio controls>`。不要把原始 PCM 直接赋给
`audio.src`。低延迟 Web Audio 调度属于可选增强，必须在用户手势后启动；断线和
取消都不自动重试，且取消应与 Provider `error` 区分。

## 模型与参数矩阵

| 家族 | 模型范围 | 格式 | 采样率 | 指令/SSML |
| --- | --- | --- | --- | --- |
| CosyVoice / Qwen-Audio | `cosyvoice-v3.5-*`、`cosyvoice-v3-*`、`cosyvoice-v2`、`qwen-audio-3.0-tts-*` | `mp3`、`pcm`、`wav`、`opus` | 8000、16000、22050、24000、44100、48000 | `instruction`；支持 `enableSsml` |
| Qwen-TTS | `qwen3-tts-*`、`qwen-tts*` | `mp3`、`wav` | 按模型/API | `instructions`、`languageType`、`optimizeInstructions` |
| MiniMax | `MiniMax/speech-2.8-*`、`MiniMax/speech-02-*` | `mp3`、`wav`、`pcm` | 16000、24000、32000、44100 | `voiceSetting` 和 `audioSetting` |

Qwen-Audio/CosyVoice 还支持 `volume`、`rate`、`pitch`、`seed`、`languageHints`、
`wordTimestampEnabled`；MiniMax 使用 `speed`、`vol`、`pitch`、`emotion`、
`bitrate` 和 `channel`。不要把这些字段放到公共请求顶层，全部置于
`providerOptions.aliyun`。模型的完整注册表表格见[阿里云百炼](/docs/providers/aliyun-bailian)。

## SSML 与 LaTeX

SSML 只在支持的模型上启用，SDK 将其作为普通 `text` 原样转发，不解析 XML、不
自动转义。示例必须作为代码内容提交：

```xml
<speak>
  <prosody rate="fast">这句话会以更快的速度朗读。</prosody>
</speak>
```

LaTeX 同样不会被渲染、验证或改写。反斜杠只需遵循 JSON/TypeScript 字符串的
转义规则：

```text
请朗读公式：$x = \\frac{-b \\pm \\sqrt{b^2-4ac}}{2a}$。
```

文本上限由调用面执行，站点 Playground 使用 10,000 个字符上限；不要通过拼接
或格式化改变用户原文。

## 播放、波形与结果生命周期

`mp3`/`wav` 的 URL 或 Base64 可以转换为 MIME 感知的 data URL/Blob URL，并用
`<audio controls>` 播放和提供下载。PCM 不是完整容器：应封装为 WAV，或只提供
下载。完成音频可以用波形渲染器展示并将进度光标与 audio element 的
`timeupdate` 同步；流式 PCM 则使用增量 peak 缓冲，不能把每个 chunk 当作文件。
解码失败时仍应尽可能保留播放/下载，并提示波形不可用。

Provider URL 和上传得到的 `oss://`/临时 URL 都可能过期。收到结果后应下载到
自己的对象存储或数据库，并保存格式、采样率等元数据；不要把临时 URL 当作永久
资源，也不要在客户端或服务端自动刷新。

## 音色克隆与设计

阿里云 Provider 提供两个独立管理器：`voiceCloning` 支持创建、列表、查询、更新、
删除；`voiceDesign` 支持创建、列表、查询、删除，不支持更新。克隆输入可以是
公开 HTTP(S) 音频 URL 或本地文件；本地文件先上传为绑定目标模型的临时 `oss://`
URL。Qwen-Audio 使用 `protocol: "qwen-audio"` 与 `prefix`，Qwen-TTS 使用
`protocol: "qwen"` 与 `preferredName`。创建的 voice id 只能用于相同
`targetModel` 的 TTS 模型。MiniMax voice cloning/design 不属于 SDK 语音资源管理器。

## Web 与 Site 凭据

`apps/web` 是服务端代理 Playground：API key 和 Authorization header 只存在于
服务端，音频请求通过服务端路由转发。`apps/site` 是 BYO-key 纯前端站点：凭据
保存在浏览器本地 key store，浏览器直连 DashScope，必须使用完整且已确认的
endpoint，并可能遇到 CORS。站点不会把凭据持久化到项目服务器。生产集成优先
使用服务端代理；错误提示不应包含 key、header 或内部堆栈。
