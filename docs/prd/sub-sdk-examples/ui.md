## 1. UI 目标与边界

Playground 是开发者体验工具，不是管理后台或多租户产品。UI 重点是让用户快速完成：配置已在服务端准备的 Provider、输入 prompt、提交请求、理解任务状态、查看结果和诊断非敏感错误。

浏览器不显示或收集 API Key，不提供账户、账单、历史图库和团队权限。

## 4. 用户旅程

| 阶段 | 用户目标 | 触点/渠道 | 用户行为 | 痛点或风险 | 情绪依据 | 产品机会 | 对应功能 |
|---|---|---|---|---|---|---|---|
| 配置 | 确认可使用的 Provider | `.env.example`、配置说明 | 配置服务端环境变量 | 变量名、deployment 或模型不清楚 | 待确认 | 按 Provider 展示必填项和状态 | `FEAT-002`、`FEAT-006` |
| 选择 | 选择合适模型 | Playground 表单 | 选择 Provider、模型和模式 | 模型能力差异可能不明显 | 待确认 | 显示能力提示和不支持状态 | `FEAT-004` |
| 输入 | 描述目标图片 | Prompt、参考图控件 | 输入 prompt、上传/提供图片 | 图片格式、大小和编辑能力限制 | 待确认 | 在提交前做可行动校验 | `FEAT-004` |
| 生成 | 获得结果 | 生成按钮、任务状态 | 提交并等待 | 异步任务耗时、超时和成本 | 待确认 | 展示状态、禁用重复提交和超时提示 | `FEAT-003`、`FEAT-005` |
| 诊断 | 理解失败原因 | 错误提示、配置说明 | 修正配置或参数 | Provider 错误可能技术化 | 待确认 | 显示稳定错误和下一步建议，不泄露敏感信息 | `FEAT-005`、`FEAT-006` |

情绪字段没有直接用户研究资料支持，均标记为待确认，不作为产品事实。

## 5. 视觉和组件规范

- 延续当前 `@workspace/ui` 和 Tailwind 设计基础，不新增独立视觉系统。
- 复用共享 Button、主题和全局 CSS；若缺少 Select、Textarea、Card、Alert 等组件，再按共享 UI 规范补充。
- Provider/model 选择使用清晰的标签、帮助文本和能力徽标，不用颜色作为唯一状态表达。
- 任务状态使用文本 + 图标/辅助说明：处理中、成功、失败、未配置、能力不支持。
- 结果预览区优先保证图片可读性，元数据使用可折叠或次要层级。
- 敏感配置说明固定放在表单或页面底部，避免把密钥输入设计成用户操作。

## 6. 通用交互

- 生成期间禁用重复提交，显示当前 Provider/model 和可取消性（若支持）。
- 未配置 Provider 时，按钮不可用并指向 `.env.example`/配置说明。
- 切换模型后清理不兼容字段或明确提示字段已被忽略；不得静默提交不支持参数。
- 空结果提供下一步操作，不显示空白区域。
- 失败状态保留用户输入，允许修正后重试；不自动切换 Provider。
- UI 不显示 API Key、Authorization、内部堆栈或原始响应 body。

## 7. 国际化、可访问性与响应式

- 当前页面 `lang="en"` 是代码库事实；产品文案语言待确认，建议首期至少保持中文/英文之一的一致性。
- 表单控件必须有可见 label、键盘可操作、焦点状态和错误关联。
- 状态更新需可被屏幕阅读器感知，不能只依赖颜色或动画。
- 桌面使用双栏，窄屏使用单栏；输入和结果图片不造成横向溢出。
- 图片预览提供替代文本；错误提示靠近相关控件并有总结区域。

## 8. UI 验收标准

- [ ] 桌面和移动宽度下表单/结果布局可用。
- [ ] Provider/model、模式、prompt 和参考图入口清晰可操作。
- [ ] 不支持能力在提交前可见并有说明。
- [ ] 处理中、成功、失败、未配置和空状态均有明确 UI。
- [ ] 结果图片、URL、MIME、尺寸和非敏感元数据显示层级清晰。
- [ ] 不存在浏览器端 API Key 输入或展示。
- [ ] 表单支持键盘操作、可见焦点、label 和错误关联。
- [ ] UI 不假设当前共享包中已经存在未确认组件。
