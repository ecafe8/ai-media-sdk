# 检查报告：`add-frontend-site` OpenSpec Change

## TL;DR

🔴 [blocking] 纯前端直连方案仍有凭证外泄、GitHub Pages 子路径路由和 Router 依赖三个实施阻塞点【main】815e1cd

## 概要（Summary）

- 检查对象：`openspec/changes/add-frontend-site/` 下的 proposal、design、6 份 spec、tasks。
- 目标：新增 `apps/site` 纯前端 Landing + Playground，浏览器直连 Provider，使用 OPFS 缓存媒体，并发布到 GitHub Pages。
- OpenSpec 结构完整，`openspec validate add-frontend-site --strict` 已通过。
- 设计方向总体一致，但部分安全约束和部署细节没有固化为可执行要求；按当前文档直接实施，存在无法正确部署或把 Key 发往非 Provider 端点的风险。

## 优点（What I liked）

- 🎉 明确保留 `apps/web`，将服务端代理版和纯前端 BYO 版作为互补形态，避免强行改造现有运行模式。
- 🎉 OPFS 原始字节 + IndexedDB 元数据 + 请求时才转 base64 的缓存方向合理，避免把膨胀后的 base64 长期存储。
- 🎉 对 video-edit 源视频保持公网 URL 的边界定义比盲目承诺本地视频上传更稳妥。
- 🎉 `tasks.md` 按工作区、数据层、缓存、组件、部署、验证分组，依赖顺序基本清晰。

## 重要问题（Major Issues / Blocking）

### 🔴 [blocking] BYO endpoint/baseUrl 可导致 API Key 被发送到任意站点

**文件**：[byo-key-store/spec.md](../openspec/changes/add-frontend-site/specs/byo-key-store/spec.md#L7-L23)、[design.md](../openspec/changes/add-frontend-site/design.md#L46-L54)

**问题**：Azure 的 `endpoint` 和 Bailian/Seedream 的 `baseUrl` 是用户可填写的字符串。纯前端 executor 会直接用这些值创建 Provider；如果用户误填、复制了恶意链接，或页面被恶意脚本诱导，Key 就会被发送到任意 HTTPS 服务。当前 spec 同时声称“仅发往对应 Provider”，但没有定义 endpoint/baseUrl 的 host 校验、协议校验、跨域自定义端点确认或风险提示。

**影响**：这是凭证泄露风险，不能仅靠“Key 存在浏览器”解决。`localStorage` 中的 Key 也会被同源 XSS 读取。

**建议修复**：

- 为每家 Provider 定义允许的默认 host 校验规则，例如 Azure 仅允许 Azure OpenAI 资源域名，Bailian 仅允许 DashScope/MaaS 域名，Ark 仅允许 Ark 域名。
- 若必须支持自定义 endpoint，增加显式“自定义端点”模式、展示完整目标 URL、二次确认，并在 spec 中明确“用户确认后可将 Key 发送至该自定义端点”。
- 在请求前再次校验最终 URL，不只在表单输入时校验；禁止 `http:`、`data:`、`javascript:`、用户名密码段和非预期端口。
- 增加恶意/错误 endpoint 的单测与浏览器网络断言，并把“同源脚本可读取 localStorage”写入隐私提示。

### 🔴 [blocking] GitHub Pages 项目子路径下 BrowserRouter 深链仍可能失效

**文件**：[site-shell/spec.md](../openspec/changes/add-frontend-site/specs/site-shell/spec.md#L21-L28)、[site-deployment/spec.md](../openspec/changes/add-frontend-site/specs/site-deployment/spec.md#L21-L42)、[design.md](../openspec/changes/add-frontend-site/design.md#L88-L92)、[tasks.md](../openspec/changes/add-frontend-site/tasks.md#L50-L54)

**问题**：方案选择正常路径的 BrowserRouter，并通过 `404.html` 兜底；同时资源 base path 默认是 `/ai-media-sdk/`。但没有规定 Router 的 `basename` 必须与 Vite base path 对齐。部署到 `https://ecafe8.github.io/ai-media-sdk/` 后，客户端可能看到 `/ai-media-sdk/playground`，而路由只声明 `/playground`，导致匹配失败。仅复制 `index.html` 为 `404.html` 不能解决 basename 不一致。

**建议修复**：

- 明确约定 `basename = import.meta.env.BASE_URL` 去除首尾斜杠后的值，或改用 HashRouter。
- 在 spec 与 tasks 中加入验收场景：项目子路径下直接访问 `/ai-media-sdk/playground`、刷新该地址、点击 Landing 到 Playground、静态 chunk 与图片全部返回 200。
- 让 Vite base、Router basename、404 fallback 和 workflow 的 `VITE_BASE_PATH` 使用同一来源，避免各自设置。

### 🔴 [blocking] 浏览器 Router 依赖写错或至少表述不完整

**文件**：[proposal.md](../openspec/changes/add-frontend-site/proposal.md#L30-L35)、[tasks.md](../openspec/changes/add-frontend-site/tasks.md#L1-L6)、[tasks.md](../openspec/changes/add-frontend-site/tasks.md#L40-L43)

**问题**：依赖清单写的是 `react-router`，但浏览器应用通常需要 `react-router-dom` 提供 `BrowserRouter`、`Routes`、`Link` 等 DOM 绑定 API；任务只说“配置 react-router”，未明确包名、版本与 `basename` 配置。按当前任务执行可能导致无法导入浏览器路由组件或产生错误的依赖重复。

**建议修复**：

- 明确使用当前仓库兼容版本的 `react-router-dom`，并在 package.json、lockfile、tasks、design 中统一名称。
- 在 `apps/site` 的最小脚手架任务中加入一个 `/` 与 `/playground` 的实际路由渲染测试，而不是只验证空白页启动。
- 若有意使用 React Router v7 的新包边界，需明确版本和实际 import 路径，并用构建验证锁定行为。

## 次要问题（Important / Non-blocking）

### 🟡 [important] OPFS 持久化被表述得过于确定

**文件**：[media-file-cache/spec.md](../openspec/changes/add-frontend-site/specs/media-file-cache/spec.md#L21-L28)、[design.md](../openspec/changes/add-frontend-site/design.md#L64-L78)

**问题**：spec 使用“跨会话持久”“免用户授权”，design 使用“磁盘级配额”，但浏览器可以在存储压力、隐私模式、用户清理站点数据时回收 OPFS；“可用”不等于“保证永久持久”。此外，`navigator.storage.persist()` 可能被拒绝，不能假设 500MB 一定可用。

**建议修复**：将要求改为“在存储未被浏览器回收且权限/配额可用时跨会话复用”；启动时调用 `navigator.storage.estimate()`，必要时尝试 `persist()`，并在 UI 显示缓存可被浏览器清理的说明。为“重启浏览器后缓存丢失”补充可验证的降级场景。

### 🟡 [important] CORS 证据不足以证明所有运行时请求都可用

**文件**：[proposal.md](../openspec/changes/add-frontend-site/proposal.md#L1-L3)、[direct-provider-execution/spec.md](../openspec/changes/add-frontend-site/specs/direct-provider-execution/spec.md#L7-L19)、[design.md](../openspec/changes/add-frontend-site/design.md#L5-L10)

**问题**：当前结论主要基于固定 host 的 OPTIONS 预检。实际站点还需要真实 POST、异步任务 GET/poll、错误响应 CORS 头、用户填写的区域/工作区 baseUrl；这些不一定与预检结果相同。

**建议修复**：把“CORS 通过”降级为已验证 host 的前置假设，并增加 provider-specific 浏览器 E2E：真实或 mock 的生成 POST、task polling、401/429/超时和自定义 endpoint 失败；运行时错误要显示“Provider 不允许浏览器直连，请改用 apps/web”类降级提示。

### 🟡 [important] 图片输入数据模型没有在任务中闭合

**文件**：[playground-media-input/spec.md](../openspec/changes/add-frontend-site/specs/playground-media-input/spec.md#L7-L19)、[tasks.md](../openspec/changes/add-frontend-site/tasks.md#L14-L18)、[tasks.md](../openspec/changes/add-frontend-site/tasks.md#L28-L38)

**问题**：现有 `apps/web` 的 `PlaygroundRequest` 使用 `referenceImageUrl` 和 `referenceImageUrls: string[]`；新 spec 要求上传值以 `{ base64, mimeType }` 传给 SDK，但 tasks 只写“URL 校验同时接受已选文件形态”，没有定义前端 request model、单值/列表到 SDK `ImageContent` 的转换边界，也没有明确 edit、i2v、r2v 三条路径各自的转换测试。

**建议修复**：在 design/spec 中定义独立的 `ImageInput = { url: string } | { base64: string; mimeType: string }` 和 `ImageInput[]`，明确 executor 如何映射到 `editImage`、`submitVideoTask` 的 `firstFrame`/`referenceImages`；增加各路径的单测，避免复制现有字符串 request 类型后再强行塞对象。

### 🟡 [important] 5MB 上限的配置来源互相矛盾，且未定义总请求上限

**文件**：[playground-media-input/spec.md](../openspec/changes/add-frontend-site/specs/playground-media-input/spec.md#L40-L47)、[design.md](../openspec/changes/add-frontend-site/design.md#L84-L97)、[tasks.md](../openspec/changes/add-frontend-site/tasks.md#L28-L32)

**问题**：spec 写“默认 5MB，可配置”，design 又写“可配置常量”，tasks 只写固定 5MB，没有配置名、运行时来源或覆盖方式。更重要的是 r2v 允许多张图片，单图均不超 5MB 仍可能形成几十 MB 的 base64 请求，Provider 仍会拒绝或浏览器内存压力过大。

**建议修复**：明确 `MAX_IMAGE_BYTES` 的唯一来源（构建时 `VITE_` 变量或固定常量二选一），同时定义单图、所有引用图总字节数和 base64 后估算请求体上限；在选择/提交前阻止超限，并提供“减少图片数量或压缩图片”的文案。5MB 应通过真实 Provider 请求验证后再作为默认值。

### 🟡 [important] 模型注册表复制会造成站点与 apps/web/SDK 漂移

**文件**：[site-shell/spec.md](../openspec/changes/add-frontend-site/specs/site-shell/spec.md#L7-L14)、[tasks.md](../openspec/changes/add-frontend-site/tasks.md#L14-L18)、[tasks.md](../openspec/changes/add-frontend-site/tasks.md#L40-L43)

**问题**：proposal/spec 要求模型矩阵与 `PLAYGROUND_MODELS` 一致，但 tasks 明确复制 `apps/web/lib/playground/registry.ts`。这会产生第二份派生注册表；以后 provider 包新增模型时，apps/site 不会自动同步，违反“由 SDK 注册表运行时派生”的目标。

**建议修复**：优先提取 provider-independent 的模型投影/label registry 到共享 package，或在 apps/site 直接从三家 provider registry 生成自己的最小 projection；禁止复制完整 `apps/web` registry。增加测试：遍历三家源 registry，确认站点展示模型集合与源集合一致。

## 建议补充

- 【建议】补充“Provider API Key 由用户自行承担费用、配额和数据处理责任”的 Landing/设置文案，并说明请求会把图片内容发送到所选 Provider。
- 【建议】补充清理机制：设置面板同时提供“清除所有 Key”和“清除所有媒体缓存”，并在删除 OPFS 文件失败时保持元数据一致性或安排启动时孤儿文件清理。
- 【建议】补充上传取消、重复点击、并行多文件上传、页面切换中断和生成取消（`AbortSignal`）的任务；否则 r2v 多文件上传可能产生竞态和残留卡片。
- 【建议】补充图片 MIME 白名单与真实文件类型检查，不能只信任 `File.type`；至少限制 png/jpeg/webp，并对 SVG 默认拒绝，避免缩略图渲染和 XSS 风险。
- 【建议】补充 OPFS/IndexedDB schema version、升级与损坏恢复策略；尤其是元数据存在但 OPFS 文件消失时应自动移除坏条目并提示重新选择。
- 【建议】补充 Provider baseUrl 的各区域配置、Azure endpoint/apiVersion/model deployment 的表单说明，以及“生成请求可能包含图片原始内容”的隐私确认。
- 【建议】将 `apps/site` 的构建、preview、部署产物检查加入 CI；除 build 外增加对 `dist/404.html`、资源 base path、无服务端代码和 source map 策略的断言。
- 【建议】补充部署权限与供应链配置：workflow 应包含 `contents: read`、`pages: write`、`id-token: write`、`actions/checkout`、Bun 安装/缓存、并发取消旧发布；这些目前只在 tasks 中概括描述。
- 【建议】为“无 CORS/Provider 端点不可用”提供切换到 `apps/web` 的链接，而不是只显示通用网络错误。

## 需订正内容

- 【严重】[design.md](../openspec/changes/add-frontend-site/design.md#L46-L54) 与 [byo-key-store/spec.md](../openspec/changes/add-frontend-site/specs/byo-key-store/spec.md#L21-L23) 将“Key 仅发往对应 Provider”写成无条件事实，但允许用户输入任意 endpoint/baseUrl。应改为“默认端点经 host 校验；自定义端点须显式确认并承担风险”，否则文档承诺与实现可能矛盾。
- 【警告】[proposal.md](../openspec/changes/add-frontend-site/proposal.md#L9-L11) 称“三家 adapter 均支持 `{ base64, mimeType }`”，但 Azure `editImage` 当前是 `NOT_IMPLEMENTED`，而 Aliyun video-edit 的 `inputVideo` 契约明确是 URL-only。应改成“所有本期实际使用的图片输入路径支持；Azure 图像编辑与 video-edit 源视频不在 base64 范围内”。
- 【警告】[design.md](../openspec/changes/add-frontend-site/design.md#L30-L36) 称“请求体不受 Vercel 4.5MB 限制，约束转为 Provider 侧”，表述不完整：纯静态站点确实没有 Vercel Function 限制，但浏览器/Provider 仍有 payload、内存、超时与 CORS 限制，不能暗示只剩 Provider 单一约束。
- 【警告】[media-file-cache/spec.md](../openspec/changes/add-frontend-site/specs/media-file-cache/spec.md#L21-L32) 说“缓存条目包含文件字节”，但同时要求 IndexedDB 只存元数据；应明确“文件字节存 OPFS，IndexedDB 只存元数据与 OPFS 文件名/版本”，避免验收与实现冲突。
- 【警告】[tasks.md](../openspec/changes/add-frontend-site/tasks.md#L52-L54) 只写 `404.html` 复制和 base path 注入，没有说明 Router basename、GitHub Actions 权限和 Pages artifact 校验，无法完整验收部署深链。
- 【警告】[proposal.md](../openspec/changes/add-frontend-site/proposal.md#L32-L35) 把 `react-router` 写入依赖但未写 `react-router-dom`；需统一实际包名和版本，避免脚手架阶段依赖错误。
