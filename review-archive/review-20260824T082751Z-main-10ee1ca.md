# Review

## TL;DR

🔴 [blocking] Voice SDK has protocol and streaming correctness gaps 【main】 10ee1ca

## Summary

The review covers commits `6ba9acc` and `10ee1ca`, including the core audio contracts, Transport streaming extension, Alibaba audio/voice provider implementation, Playground registry changes, tests, and docs.

## What I liked

- The implementation reuses the existing `Transport`, `SdkError`, model instance, and provider factory boundaries.
- Qwen-Audio, Qwen-TTS, and MiniMax are separated at the request-building level.
- Voice cloning and voice design are exposed as distinct managers.
- Existing repository lint, typecheck, build, and test commands pass.

## Major Issues / Blocking

### 🔴 [blocking] Audio models are projected as image models in the web Playground

**File**: `apps/web/lib/playground/registry.ts#L175-L184`

**Problem**: `fromAliyun()` maps every modality other than `video` to `image`:

```ts
modality: caps.modality === "video" ? "video" : "image"
```

New Alibaba audio models therefore become image models and can be selected by image flows. The site avoids the issue by returning `undefined`, but the web Playground does not.

**Suggested fix**: Return `"audio"` for audio capability, or explicitly exclude audio models from the image/video Playground projection. Add a regression test asserting no audio model is exposed as an image model.

### 🔴 [blocking] SSE parser drops the final event when the response has no trailing newline

**File**: `packages/provider-aliyun-bailian/src/provider/audio.ts#L280-L292`

**Problem**: The parser only processes complete lines inside `for await`. Any final `data: {...}` event left in `pending` after the body ends is silently discarded. A valid final `finish_reason: "stop"` event can therefore never produce the `complete` event or final URL.

**Suggested fix**: After the body loop, parse the remaining `pending` line using the same event parser. Add a fixture where the final SSE event has no trailing `\\n`.

### 🔴 [blocking] Streaming Transport bypasses timeout/retry error classification

**File**: `packages/ai-media-sdk/src/transport/http-transport.ts#L57-L80`

**Problem**: `sendStream()` calls `fetchImpl()` directly and does not catch `AbortError`, timeout, or network failures. Unlike `send()`, it does not convert them to `TransportError`, does not retry retryable failures, and does not apply `defaultTimeoutMs` when `request.timeoutMs` is omitted.

**Impact**: Streaming requests can hang indefinitely and expose raw `TypeError`/abort exceptions instead of the repository's stable transport error contract.

**Suggested fix**: Define and test explicit streaming timeout behavior, propagate the effective default timeout, and map network/timeout failures consistently. If retries are intentionally excluded for streaming, document that decision in the Transport contract and still classify failures.

### 🔴 [blocking] Voice manager chooses protocol but does not validate target model or input URL/Data URL

**File**: `packages/provider-aliyun-bailian/src/provider/voice.ts#L158-L200`

**Problem**: `sendClone()` only checks that some audio field exists and name syntax. It accepts invalid schemes, arbitrary MIME Data URLs, missing/invalid language values, and target models unsupported by the selected protocol. The `audioUrl` passed to Qwen-TTS is also wrapped as `{ data: audioUrl }` without validating that it is a public URL or supported Data URL.

**Suggested fix**: Validate `http:`/`https:` URL forms, allowed `audio/wav`, `audio/mpeg`, `audio/mp4` Data URLs, protocol-specific languages, required protocol/model combinations, and target-model allowlists before Transport. Add negative tests asserting zero transport calls.

## Important Issues / Non-blocking

### 🟡 [important] `VoiceDesignManager` always sends model IDs that are not caller-selectable

**File**: `packages/provider-aliyun-bailian/src/provider/voice.ts#L203-L251`

**Problem**: The public input accepts `targetModel`, but the resource protocol model is inferred only from `protocol`, and there is no registry validation. This permits using `qwen-audio` with an arbitrary target model and does not distinguish the documented Qwen-Audio/CosyVoice design targets from Qwen design targets.

**Suggested fix**: Add explicit cloning/design model registry metadata and reject invalid `targetModel` values before sending.

### 🟡 [important] TTS option types are broad but runtime validation is absent

**File**: `packages/provider-aliyun-bailian/src/provider/audio.ts#L13-L60`

**Problem**: `readAudioOptions()` is an unchecked cast. Unsupported fields and invalid values are accepted and forwarded, despite the change contract requiring model-specific validation. Qwen-Audio-only and Qwen-TTS-only options are also present in the same interface.

**Suggested fix**: Use separate option types and runtime validators per family/model. Reject invalid ranges for sample rate, volume, rate, pitch, seed, language, format, channel, bitrate, and instruction/SSML dependencies.

### 🟡 [important] SSE event parser conflates any audio data with `sentence-synthesis`

**File**: `packages/provider-aliyun-bailian/src/provider/audio.ts#L305-L361`

**Problem**: The parser ignores the provider event type and emits `sentence-synthesis` whenever `audio.data` is present. It does not preserve `finish_reason`, request ID, usage, or sentence-end usage, and it assumes every chunk is PCM, including MiniMax/Qwen protocol differences.

**Suggested fix**: Validate the event type, preserve request/usage metadata, model encoding semantics, and explicitly handle `sentence-begin`, `sentence-synthesis`, `sentence-end`, and terminal events. Add fixtures for each event family.

### 🟡 [important] Provider error and transport failures are not consistently sanitized in audio/voice paths

**Files**: `packages/provider-aliyun-bailian/src/provider/audio.ts#L134-L145`, `packages/provider-aliyun-bailian/src/provider/voice.ts#L294-L311`

**Problem**: Audio and voice calls do not catch `TransportError` and map it through the provider's established transport error mapper. Raw network/timeout exceptions can escape. Voice HTTP errors also discard provider `code`, `message`, and `request_id`, weakening diagnostics.

**Suggested fix**: Reuse a shared transport-error mapper, redact API keys from provider messages, and retain sanitized provider code/request ID in `SdkError` or raw metadata.
